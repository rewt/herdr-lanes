## Findings
- [Moderate] lane.mjs:2009 - close still exits nonzero with "lane closed; metadata update failed" when the configured registry is an external absolute path, a configuration REFERENCE documents as a readable board input that simply cannot receive automated records, so every close in such a repository reports failure after the worktree was removed and the branch deleted; this is the same unusable-exit-status defect as round-1 Moderate 2, whose fix covered only record read errors and not policy refusals; Fix: distinguish a preflight policy refusal (not repository-local, unignored, or tracked) from a write failure, emit the refusal on stderr as a warning like the read errors on the next line, keep the nonzero exit for an actual done-marker write failure, and state that split in the REFERENCE close section.
- [Minor] lane.mjs:991 - the inline goal fallback is the only goal path that is not fence-aware, so an inline prompt whose first nonempty line opens a fenced block records the fence marker itself as the goal instead of any real text, while the identical file-brief input yields the first prose line; Fix: call firstProseLine for the inline branch as well, so both branches skip fenced content and an all-fence prompt falls back to the topic.
- [Minor] lane.mjs:990 - applying firstBriefHeading to inline prompts now scans the whole prompt, so an inline brief that opens with the operator's instruction and later contains any heading records that later heading as the goal, a regression from the previous first-nonempty-line behavior that the round-1 remedy did not intend; Fix: for inline prompts use the first nonempty content line and strip ATX heading syntax only when that first line is itself a heading, which keeps the review template goal correct and restores prose-first inline goals; this and the previous finding share that one replacement.
- [Minor] lane.mjs:1123 - the record's server field re-derives the default Herdr socket path as a second copy of the expression in board/herdr-client.mjs:7, so changing the client default alone would make every new record name a socket the board never connects to; Fix: export one socket-path helper and call it from both places.
