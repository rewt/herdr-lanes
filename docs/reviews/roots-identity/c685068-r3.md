# Review r3 - roots-identity (test isolation pass)

Reviewed commit: c685068edab7954805e129420487f501ea2c854f

Verdict: **READY**

Read-only confirmation of the test-only correction made after a promotion run failed on
environment-level Git configuration injected by the invoking session. This pass ran no
build, test or validation command; the reported passing run from the injecting
environment is taken as given rather than reproduced. No tracked file was modified by
this review.

## Findings

**Environment-level configuration is fully cleared.** The new helper removes the bare
`GIT_CONFIG` variable and every name beginning with `GIT_CONFIG_`, which covers the
pair-count variable and every numbered key and value regardless of how many pairs are
injected. It also removes author, committer and address variables, which override
identity by a different route.

**The replacement configuration is set correctly and in the right order.** An empty
global configuration file and the system-configuration-disabled flag are applied after
the removal loop, so an inherited value of either name cannot survive. The global file
is created under the system temp directory at module load and removed by a suite-level
teardown, satisfying the temporary-fixture and cleanup rule. Pointing at an explicit
global file also supersedes the desktop-standard configuration location, which is why
the home variable is correctly left alone: several tests set it deliberately to exercise
parent-configuration discovery and the home boundary.

**Coverage is complete for fixtures that read identity or home.** Three seams are
closed: the shared Git helper now routes through the hermetic wrapper, so every helper
call including the identity writes and all commits is covered; each remaining direct Git
invocation is converted, namely repository initialization, the bare clone and its linked
worktree, the three foreign and other-repository initializations, the separate
Git-directory initialization, and the reference-existence probe; and lane child
processes are covered both at fixture construction and again at each spawn, so ad-hoc
environments built by individual tests are sanitized at the call site rather than by
convention. A search of the resulting file finds no unsanitized Git invocation left.

**No product file is touched.** The commit changes the maintenance log and the test
suite only. The CLI, the README, the reference, the report, the specification tree and
the review records are all absent from the diff.

**Nothing is weakened.** No assertion was removed or loosened, no test was skipped, and
the deliberate negative-control mechanism is untouched. The identity scenario is
strengthened: the local-configuration comparison and the author-name check now resolve
against a controlled empty global with system configuration disabled, instead of
whatever the ambient environment supplied. This masks no product defect, because the CLI
never wrote identity and the failure was the harness reading ambient configuration that
legitimately outranks a repository-local value.

## Nits, none blocking

One lane invocation still bypasses the shared spawn helper and relies on the fixture
environment already being hermetic rather than being sanitized at the call site like
every other spawn; it is safe today because that test exercises only the agent-cwd
guard, but it is inconsistent with the pattern the rest of the file now follows. The
board test suite still invokes Git without sanitization and its fixtures commit, so they
read identity; that is outside this commit's scope, and the reported full-suite pass
from the injecting environment is evidence they survive that particular injection,
though they are not hermetic in principle. Finally, clearing the author and committer
variables means the environment half of the delta specification's git-owned identity
scenario is no longer exercised; it was not asserted before this commit either, so
nothing regressed and the gap simply persists.

## Limits

Nothing was executed in this pass: no suite, no negative control, no validator, no
fixture probe. The claim that the previously failing run now passes rests entirely on
the reported re-run from the injecting environment. This review read the commit's
difference and the resulting test file only.

This record is evidence about one commit. It is not a promotion gate, and promotion
revalidates independently.
