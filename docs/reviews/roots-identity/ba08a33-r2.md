## New finding

**minor-A - the Git-fallback path in `open` reuses a stale workspace snapshot.**
`lane.mjs:765-772` refreshes the snapshot only after a successful Herdr worktree
creation. On the fallback branch the pre-creation snapshot is passed to the workspace
repair helper, whose staleness check refuses by default. If a fresh worktree listing
reports an open workspace for the path that the snapshot lacks, `open` exits one with a
repository identity mismatch for a lane it just created correctly. Before this commit
the helper always fetched its own listing, so this could not happen. Reaching it needs
Herdr running and a workspace opened for the path between the snapshot and the check -
a creation that opens the workspace but reports failure, or a concurrent open from
another session against a shared server. It fails closed rather than using the wrong
workspace, and the ordinary paths are covered and green, so this is not a blocker. Fix:
refresh the snapshot after either creation path, or pass nothing on the fallback branch
so the helper refetches. The same shape exists in dispatch with a much shorter window.
