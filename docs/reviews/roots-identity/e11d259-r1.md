# Review r1 - roots-identity

Reviewed commit: e11d25907c5be11ce2f7aa8f3f03acc192d59987

Verdict: **READY**

Independent review of one commit over the change's merge base, examined as
`git diff main...HEAD`. Every requirement and scenario in the repository-identity delta
spec is implemented and covered by an offline test, and all four budgeted verifications
reproduce the engineer report's numbers. No blocker and no major finding; only minor-1
breaks a stated rule, and it is one word in a specification document. No tracked file
was modified by this review.

## Findings

**minor-1 - the synced spec is not verbatim.**
`openspec/specs/repository-identity/spec.md:31` renders the control-resolution sentence
as "verified git paths" where the approved delta at
`openspec/changes/roots-identity/specs/repository-identity/spec.md:31` says "verified
paths". The workflow requires ADDED requirements to become the Requirements section
unchanged, and the edit will leave the archived change and the current spec disagreeing
after promotion. Every other line of the two files is byte-identical. Restore the delta
wording, or amend the delta in the same commit.

**minor-2 - bare-repository refusal is wider than the design scopes it.** Canonical
checkout resolution runs at module load (`lane.mjs:86-109`), so a linked checkout of a
bare repository fails every subcommand, including read-only `lane config` and
`lane status`, where the design scopes that failure to lane mutations. The message is
clear and refusing is safer than guessing, but this reduces behavior against the
previous commit for the bare-plus-worktrees layout. Resolve the canonical checkout
lazily for read-only commands, or state in `docs/REFERENCE.md` that the layout is
unsupported outright.

**minor-3 - the legacy default root can be refused, undocumented.** `lane.mjs:505-508`
refuses destinations inside another repository, as specified. When a home directory is
itself a checkout, that makes the documented default root at `docs/REFERENCE.md:106`
unusable for every lane, with no fallback. The behavior is correct, but no document
warns that the default profile, rather than a configured one, can be rejected, and the
troubleshooting row at `docs/REFERENCE.md:384` reads as advice about a configured base.
Say so in the worktree-root precedence section, pointing at a root outside any checkout.

**minor-4 - a missing worktree is reported as a foreign one.** `lane.mjs:421` reports a
deleted lane directory as not belonging to the canonical common directory, because the
identity lookup returns nothing both for a foreign checkout and for an absent path. The
remedy is pruning, not ownership. This still improves on the previous commit, which
aborted with an unhandled stack trace here. Test for the missing entry first.

**minor-5 - close discards stale Herdr metadata silently.** Dispatch refuses a mismatched
workspace outright (`lane.mjs:569-590`); close skips it (`lane.mjs:1034`) and falls
through to a git-only removal with no output. Not using the metadata satisfies the
requirement, and refusing close outright would strand the lane, but the operator is
never told a stale workspace was left behind. One note on stderr would fix that.

**nit-1 - agent-name uniqueness is probabilistic.** `lane.mjs:657-663` combines an
identity digest with random bytes and never consults the live agent list, although a
lookup helper already exists. Collision risk is negligible and the dispatch retry loop
regenerates the name, so this is a wording gap against the requirement, not a defect.
The stem there is also sliced twice to the same length; the second slice is dead.

**nit-2 - a quoting option has no effect.** The path-quoting configuration passed at
`lane.mjs:94` and `lane.mjs:389` does not apply to `git worktree list --porcelain`;
output was byte-identical with and without it on a worktree named with combining marks
and a multi-code-point emoji. Drop it, or comment why it is kept.

**nit-3 - repeated workspace listings.** `open` spawns `herdr workspace list` twice and
`dispatch` up to three times; one listing threaded through label selection would do.

**nit-4 - the failing-first list is one short.** The report names eight intended
pre-implementation failures. The pre-existing precedence test at
`test/lane.test.mjs:887-890` also flipped to expect a refusal and could not have passed
against the earlier implementation, so the arithmetic points to nine. No behavior is
left unobserved: the same refusal is covered by a new test that is in the recorded
eight. Only the count is off.

## Evidence

`npm test` passed 67 of 67 with no skips. The deliberate negative control failed all 67
with zero passes, so every test has a working control. With the Herdr executable removed
from the path, 66 passed and one skipped with the explicit reason "herdr is absent;
herdr-dependent tests are skipped", and git-only open, status, promote and close
coverage stayed active. Strict OpenSpec validation passed 13 of 13 with telemetry
disabled and concurrency one. `git diff --check` was clean, and a scan of every added
line for host paths, personal names, socket paths, credentials and unrelated repository
names found nothing. Each run followed a clear load probe.

Amendment A1 matches the approved text in `openspec/README.md` byte for byte, appended
to the end of the product contract with nothing else altered in `AGENTS.md`. Within
`openspec/`, only the change's task checkbox and the new capability spec were touched.

Beyond the suite, four scenarios were reproduced in temporary repositories under the
system temp directory, all removed afterwards. Two repositories deliberately sharing one
base: the second open refused by name, the occupant's head commit unchanged, and no lane
branch created. A bare repository and a linked checkout of one: both refused with a
named message. A deleted lane directory: a readable refusal where the earlier
implementation crashed. A detached lane worktree: no worktree reported, exit zero, as
before. The test double's protocol field names match a real Herdr `worktree list` and
`workspace list`, and the `--label` option the change relies on is present in that
server's help for both `worktree create` and `worktree open`.

Label arithmetic was checked by hand: the compact form sums to exactly the 64 code-point
bound at the specified fragment budgets, the fragment builder reserves room for its
ellipsis so it can never exceed a budget, and digest lengthening shrinks fragments to a
floor that holds the bound at every length. The recomputed length of the Unicode
fixture's label agrees with the figure in the report.

## Limits

No workspace was created, opened, dispatched, focused or removed on a live Herdr server,
so real label acceptance, parent attachment and terminal rendering are unexercised. The
pre-implementation baseline was not re-run; nit-4 is arithmetic on the final test file,
not a measurement. The digest-lengthening branch needs a genuine hash-prefix collision
and was reasoned about but not executed, and no path-creation race was staged. Review
ran on macOS only, so no Linux, Windows or case-sensitive filesystem behavior was
observed. Submodule checkouts, no longer disclaimed in the reference, and
permission-denied ancestors during path resolution were not tested.

This record is evidence about one commit. It is not a promotion gate, and promotion
revalidates independently.
