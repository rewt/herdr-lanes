## Findings

All twelve previous findings are resolved, several more thoroughly than requested. The two majors
were the size of the review change and the under-specified sanitization policy.

The review change now carries a pre-agreed split point that partitions all eight of its
requirements without overlap or gap: the first slice owns source and round resolution, the private
output and check budget, the record schema, the unchanged-lane enforcement, dispatch and bounded
observation, and offline tests and documentation; the second owns the sanitized public record and a
newly added publication-boundary requirement. The boundary is genuine rather than cosmetic, because
the unchanged-lane requirement was retargeted from "before writing public output" to "before
accepting a private review result", and the publication precondition was moved into its own
requirement. The first slice therefore ends at a validated private verdict with exit 0 or 1, prints
the private path on the error stream and creates no public file. Tests are assigned per slice and
there is no feature flag or automatic transition.

Sanitization is now implementable without invention. Alias inputs are an explicit table with
categories, handling of empty and unreadable sources, case-insensitive deduplication, category
precedence and injected test values. The match rule is stated: case-insensitive matching at whole
path segments or Unicode word boundaries, longest alias first, never a substring inside an
unrelated word, with unaffected text preserved. Placeholders are a fixed four-entry vocabulary with
per-category counts including zero, separately counted relative-path conversions, and reserved-atom
status so a reviewer cannot preinsert them. Five concrete refusal triggers replace the previously
circular wording, covering ambiguous aliases defined as one declared token being a proper
case-insensitive substring of another, protected finding locations and identity metadata,
undelimited absolute paths, a restricted ASCII payload class with named encoding and markup
rejections, and residual or non-idempotent output. The order of operations is fixed.

The remaining ten findings are also resolved: reviewers may create nothing inside the reviewed
worktree including ignored scratch, with all fixtures under the system temporary directory; the
amendment text itself now distinguishes documented public vendor identifiers from prohibited
organization-specific defaults; review refusals must bypass the shared exit-1 failure helper and
tests must assert exactly 2 with no verdict output; the changed meaning of the explicit
configuration override is documented as a third deliberate behavior change and backed by modified
blocks against the delivered configuration requirements; the report and the guide now agree that
the tool generates the public projection; the pending Herdr amendment names review dispatch;
repository-map maintenance is authorized as documentation work in both briefs; configuring a review
route before shipped defaults arrive is documented; late-publication recovery is specified in
detail; and the unpinned ordinary-review effort is stated for explicit ratification.
