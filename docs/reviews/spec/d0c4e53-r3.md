# Review — specification addendum: foreground review and built-in configuration

Reviewed commit: d0c4e53ecb21570564b25ae360f17ff1c18ad4b2
Round: 3 (independent review, documentation-only change)

Verdict: READY with findings. This round predates the PASS/NEEDS-WORK/FAIL vocabulary that
`review-cli` itself specifies; READY is retained for consistency with rounds 1 and 2.

## Scope reviewed

`git diff main...HEAD` against parent `55cd44c`: eleven Markdown files adding two OpenSpec
changes, `review-cli` and `default-config`, plus guide, report and handoff updates. No product
code, tests, package manifests, ignore rules or contract file were touched.

The addendum is faithful to its requirements. Present and specified: a packaged review template
rendered with literal placeholders; one dispatch through the existing path with a review route and
no engineer fallback; a bounded foreground wait with a documented timeout; exit by verdict; a
machine-checked v1 record schema whose first line is the verdict and whose full reviewed commit is
compared against both the captured and the current HEAD; tagged findings with file, line and a
concrete fix; a mandatory re-executed section requiring an observed negative-control or mutation
witness behind every tests-pass claim; mandatory non-claims and unverified sections; the private
record as required, explicitly permitted reviewer output; read-only enforced by HEAD and clean-tree
checks before and after; a public record generated only by the tool after verified sanitization; and
an explicit round with documented tier escalation and no automatic loop. For configuration: eight
overridable built-in role routes, a shipped dispatch profile equal to the shipped engineer profile,
templates resolved from the installation, built-in source provenance in configuration inspection,
and an explicit amendment (A5) for shipping public vendor defaults.

Three choices are better than the brief required and should be kept: the private record lives in
the canonical checkout's ignored directory so it cannot dirty the lane under review; the generated
public record stays untracked so validation and promotion keep refusing until an operator commits
it, and that refusal is an acceptance test; and the shared engineering delivery rules are now
separated from reviewer permissions, removing the conflict where a dispatched reviewer inherited
instructions to add tests and commit.

## Findings

### Major

- [Major] `openspec/changes/review-cli/tasks.md`:35 — the brief is one checkbox over 7
  requirements, 14 scenarios and a 243-line design, against 4/11/61 and 3/4/53 for the two largest
  previously accepted lanes. It combines template authoring, source and round resolution, gate
  disclosure, before/after integrity checks, a record-schema validator, a sanitization and
  projection engine, bounded dispatch with timeout and signal handling, three exit paths,
  documentation, and eight enumerated groups of failing tests. Fix: add a pre-agreed split point to
  its design, as two earlier changes already carry — first slice ends at exit 0/1 on a validated
  private record with no public output, which is independently useful; second slice adds
  sanitization, projection and the publication boundary. `openspec/changes/default-config` is
  borderline by the same measure, with a clean seam between the route layer and template resolution.
- [Major] `openspec/changes/review-cli/design.md`:180 — the sanitization design is sound in
  principle, because the reviewer declares private identifiers and the checker validates against a
  known set, rescans and requires idempotence. Four mechanics are undefined and would be invented
  differently by different implementers: the alias sources behind "local OS identity/hostname
  aliases"; the match rule, where substring matching on a short identifier would corrupt unrelated
  finding text, so whole-segment or word-boundary and case-insensitive matching should be stated; a
  fixed placeholder vocabulary, without which the published substitution counts are not comparable
  across rounds; and the refusal triggers "ambiguous token replacement" and "unsupported markup"
  (same line 189), which are currently defined only by their own names. Fix: enumerate the alias
  sources, state the match rule, fix the placeholder names, and define ambiguity concretely, for
  example a declared token occurring inside another declared token or inside a file and line
  reference, together with a restricted character class for projected strings.

### Minor

- [Minor] `openspec/changes/review-cli/design.md`:84 — the required-output section permits
  "temporary test fixtures" without saying where they may live, while the after-check refuses on
  untracked files as well as tracked ones. A reviewer that writes scratch files in its working
  directory loses the whole round at the final check with no verdict. Fix: state that nothing may
  be created inside the reviewed worktree, tracked or untracked, and that fixtures live under the
  system temporary directory, matching the existing test convention.
- [Minor] `openspec/README.md`:169 — A5 replaces the repository-neutral configuration rule and
  preserves both halves of it, but the rule that most directly forbids shipped vendor defaults is
  the separate public-content rule against organization-specific defaults, which A5 does not touch
  even though the proposal argues against exactly that phrase. Fix: add a clause stating that
  documented public vendor product identifiers used as overridable defaults are not
  organization-specific defaults. A5 is otherwise necessary and tightly scoped: lowest precedence
  only, no paths, accounts, credentials, endpoints or identities, kind and model still
  configurable, and visible failure with no substitution or retry.
- [Minor] `openspec/changes/review-cli/design.md`:215 — exit 1 is reserved for a valid
  NEEDS-WORK or FAIL verdict, while every existing command fails through a shared helper that exits
  1. An implementation that reuses that helper for a usage error would emit exit 1 with no verdict
  on stdout, and a caller keying on the exit code alone would read a flag typo as a failed review.
  Fix: require that refusals bypass the shared exit-1 failure path, and assert exit 2 explicitly in
  the tests rather than "nonzero".
- [Minor] `openspec/changes/default-config/design.md`:62 — keeping built-ins beneath an explicit
  configuration file narrows the previously delivered meaning of that override, in which the single
  selected file was the whole configuration. The design lists two deliberate behavior changes
  nearby but not this third one. Fix: list it, with the practical consequence that a partial
  explicit file now inherits built-in routes it did not declare.
- [Minor] `docs/SPEC-20260908.md`:150 — the decision table still describes review records as
  hand-written evidence, while the guide's shared decisions were correctly updated to say the tool
  generates the sanitized public projection. Fix: one clause in that row, retaining the statement
  that reviews never become promotion policy.
- [Minor] `openspec/README.md`:153 — the pending Herdr-requirement amendment enumerates dispatch,
  dispatch-from-idea, live discovery and session focus. The new review command also dispatches and
  can ship before that amendment is applied. Fix: while the text is still unapplied, add review
  dispatch to the list or generalize to dispatch in any form.

### Nit

- [Nit] `AGENTS.md`:22 — the repository map will omit the new review template and the new
  top-level defaults directory, and no lane is authorized to edit that file except for the approved
  amendment. Add map maintenance to both scopes; a map line is not a contract amendment.
- [Nit] `openspec/changes/review-cli/design.md`:11 — the command is inert until a review route
  exists, and the change that ships one comes later. Add one sentence to the documentation
  deliverable telling an operator to configure that route first.
- [Nit] `openspec/changes/review-cli/design.md`:69 — after a failure at the publication boundary
  the public file may already exist, and re-running the same round then refuses because the output
  exists. Name that recovery case specifically rather than leaving it to a general recovery
  section.
- [Nit] `openspec/changes/default-config/design.md`:23 — the shipped review route passes no effort
  argument, deliberately, so the agent chooses its own default. The rationale is sound; confirm the
  intent explicitly rather than leaving it to be discovered.
